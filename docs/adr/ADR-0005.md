## Why

ADR-0003 dropped the hand-kept `clientOnlyOps` list. Instead, about 26 platform-only handlers in IdentityX opened with `handlers.RequireClientOnly`. Two problems stayed:

1. **Each handler had to remember.** A new handler that skipped the line quietly exposed more. The test meant to catch that, `clientOnlyMethods` in `internal/handlers/handlers_test.go`, was itself a hand-kept copy of the spec.
2. **Two places decided who may call a route.** The scope check sat in the HTTP handlers, the role checks (`CheckProject`, `CheckOrg`, `CheckPlatform`) in the operations. Scope couldn't be tested without HTTP, and `RequireProjectClientOnly` sat in `models` with no caller.

The spec already decides authentication: its security blocks become the auth chains, checked at boot. Scope is the same kind of fact, a rule about which kind of caller may use an operation, so it belongs there too.

## Decision

- An operation declares `x-scope: <name>`. There's no document-wide default, and no `x-scope` means no restriction.
- `lib/go/authz` reads `x-scope` in `SpecOperations`. `Primitives` gains `Scopes map[string]ScopeChecker`, where a `ScopeChecker` is `func(ctx) error` reading the identity the auth middleware stored. With no registry, scopes are off, so backends that don't use them are untouched.
- `NewResolver` stops the boot if a declared scope has no checker, or if an operation has `x-scope` but `security: []` (a scope needs a signed-in caller). The chain runs `[setupGuard?, authn, scope]`.
- IdentityX registers its checkers in its access-check module: `authz.Service.ScopeCheckers()` returns `{"platform-only": ...}`, the old `RequireClientOnly` logic. `models.RequireClientOnly` and the unused `models.RequireProjectClientOnly` are deleted. A new scope is one spec line and one checker.
- Handlers lose their guard lines and only bind HTTP. The `clientOnlyMethods` list is deleted. The parity test (`TestAuthMatrixMatchesSpec`) builds its expected chains, scope included, from the spec.
- `getPlatformProfile` was marked public (`security: []`) in the spec but guarded in its handler, so it returned 401 to everyone. It's now `bearerAuth` with `x-scope: platform-only`, matching how the IdentityX UI uses it.

## Consequences

- Removing an `x-scope` is a spec change that shows up in review, and the parity test pins what's exposed. A handler can no longer forget the check.
- Scope checkers are plain functions, tested without HTTP next to the role checks.
- Any backend can declare scopes and register its own checkers without touching the resolver.
- This replaces ADR-0003's note that scope isn't part of the chain. The rest of ADR-0003 stands.
