# ADR-0009 — The Harness owns the strict-mounting seam (amends ADR-0003)

- **Status:** accepted (amends ADR-0003)
- **Date:** 2026-09-18
- **Scope:** `lib/go/httpserver`, `api/{identityx,informd,payssage,univents}/internal/app`, `lib/go/authz`

## Context

ADR-0003 moved the auth dispatch into `lib/httpserver` but left the residual
glue per backend: "only conversions and param-binding error mapping stay in
the backend." That residual grew into the largest copy-paste in the repo:

- `mountStrict` (~30 LOC of policy-bearing glue) ×4, differing only by
  generated-package import and 0–2 extra lines;
- `adapt` (byte-identical cast) ×4;
- `auth_dispatch.go` (identical pass-through into `authz.NewResolver`)
  ×4;
- the `middlewares` struct (a subset of `authz.Primitives`) ×4;
- the param-binding error map ×4 — already drifted: only identityx handled
  `RequiredHeaderError`.

Every line is the same interface hand-copied; the drift was live. ADR-0003
rejected "generic/reflection-based param-error mapping in lib" when the
alternative was a ~13-line switch — the rejection assumed one copy. With
four copies drifting, the trade changed.

## Decision

- `httpserver.MountStrict[HF, ...]` — one generic function owns the whole
  mount: validation middleware, then fail-closed auth dispatch, in that
  order, plus the unified error mapping. The generated package's surface
  crosses the seam as function values (`NewStrictHandlerWithOptions`,
  `HandlerWithOptions`) and type parameters; the per-backend `mountStrict`
  shrinks to a pure-configuration adapter (~15 lines: type names, options
  structs, extras like payssage/univents' raw-request webhook middleware).
- `httpserver.ParamBindingErrorHandler` — the param-binding error map is
  unified to the superset (required params, invalid formats, required
  headers) and lives once. The generated error classes are oapi-codegen's,
  machine-owned, and structurally identical across the four packages except
  for their package path, so the harness classifies by type name and reads
  `ParamName` by reflection — the harness's one concession to the codegen,
  now justified by four copies drifting.
- `adapt` dies into an internal generic cast (`adaptTo`), backed by two
  structural constraints (`StrictHandlerFuncT`, `StrictMiddlewareFuncT`)
  that capture the generated types' shared shape.
- `auth_dispatch.go` ×4 is deleted: each backend's `CreateRouter` (and test
  helpers) calls `authz.NewResolver(spec.OpenAPISpec, primitives, options)`
  directly — the per-backend file was a pure pass-through.
- The `middlewares` struct ×4 is deleted; `initMiddlewares` returns
  `authz.Primitives` directly. Middleware **construction** stays
  per-backend (identityx's is internal-keyed, consumers' is
  idxClient-keyed); construction is policy, dispatch is not.

## Consequences

- Deleting a per-backend app's `strict.go`/`auth_dispatch.go`: complexity
  that reappeared ×4 now sits once, behind the Harness.
- Error-mapping drift is structurally impossible; a header-error case added
  in oapi-codegen is one lib edit, not four backend edits.
- The route-parity and auth-matrix tests (`parity_test.go` ×4, ~254
  hand-written stub methods) are deleted with this change: once
  `MountStrict` mounts the generated server by construction, route parity
  is tautological and the auth matrix is already enforced by the resolver's
  fail-closed boot validation.
- `telemetry.Log()` (global logger, `TEST_MODE` env branch) remains
  out of scope — future work, unchanged by this ADR.
