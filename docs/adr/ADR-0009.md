## Why

ADR-0003 moved auth dispatch into `lib/go/httpserver` but left some glue in each backend, on the idea that it would be small. It became the biggest copy-paste in the repo, four times over:

- `mountStrict`, about 30 lines that decide behavior, differing only by import and a line or two
- `adapt`, an identical cast
- `auth_dispatch.go`, a straight pass-through to `authz.NewResolver`
- a `middlewares` struct that was a subset of `authz.Primitives`
- the param-binding error map, which had already drifted: only IdentityX handled `RequiredHeaderError`

ADR-0003 chose a small switch per backend over a generic mapping that reads type names. That was right for one copy. With four copies drifting, it wasn't any more.

## Decision

- **One generic `httpserver.MountStrict`** does the whole mount: validation, then fail-closed auth dispatch, in that order, plus error mapping. The generated package's constructors (`NewStrictHandlerWithOptions`, `HandlerWithOptions`) are passed in as functions and type parameters.
- **One param-binding error map**, `httpserver.ParamBindingErrorHandler`, covering everything any backend handled: missing params, bad formats, missing headers. oapi-codegen's error types are the same in every generated package except the import path, so the harness matches them by type name and reads `ParamName` by reflection. That's the one place the harness leans on codegen details, and four drifting copies justify it.
- **`adapt` becomes an internal generic cast**, `adaptTo`, backed by two constraints (`StrictHandlerFuncT`, `StrictMiddlewareFuncT`) that describe the generated types' shape.
- **`auth_dispatch.go` is deleted.** Each backend calls `authz.NewResolver(spec.OpenAPISpec, primitives, options)` directly.
- **The `middlewares` struct is deleted.** `initMiddlewares` returns `authz.Primitives`. Building the middlewares stays in each backend, because IdentityX builds them from its own internals and the others from the IdentityX client. How a middleware is built is each backend's policy. How it's dispatched isn't.
- **The per-backend mount is generated.** `tools/go/strictmount` writes `openapi.Mount` into each generated package after oapi-codegen, and `Build` calls `openapi.Mount(r, srv, chains, extraMiddlewares...)`. Nobody writes `mountStrict` by hand.

## Consequences

- Code that existed four times now exists once, in the harness.
- Error mapping can't drift. A new error case in oapi-codegen is one lib change.
- The route-parity and auth-matrix tests (`parity_test.go` in each backend, about 254 hand-written stubs) are deleted. `MountStrict` mounts the generated server directly, so route parity always holds, and the resolver's boot checks already enforce the auth matrix.
- `telemetry.Log()` is still out of scope.

## Changes

- **2026-10-29:** the per-backend `mountStrict` is generated by `tools/go/strictmount` instead of written by hand.
