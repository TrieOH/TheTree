## Why

After ADR-0017, the only `fun` package still doing work was `fun/middlewares`: the stack every backend runs (real IP, request ID, access log, metrics, recover, timeout, body limit, rate limit, CORS) and the JWT and API key auth primitives. It's about 400 lines in use, mostly plain stdlib, and it reached our error writer only through a global `SetErrorWriter` hook. It had four bugs:

- The rate limiter was keyed on `r.RemoteAddr`, which includes the port when there's no proxy header. Every new connection got a fresh bucket.
- The limiter's map of clients never shrank.
- The access log read the request ID from the request header, so an ID the middleware created itself was logged empty.
- Real IP fell back to the leftmost `X-Forwarded-For`, which the client controls. Cloudflare doesn't send that header, so in production this could only be reached by a client sending it without `CF-Connecting-IP`, and Cloudflare always sets that one.

## Decision

- **The stack lives in `lib/go/httpserver/middleware.go`,** unexported except `CORS` (a test checks the real config) and `RequestIDFromCtx`. `rs/cors` and `x/time/rate` stay underneath.
- **Auth primitives come from `httpserver.Authenticators{JWT, APIKey}.Primitives()`.** Each authenticator takes the raw credential and returns the context with the identity on it, and any error is a 401. `lib/go/backend/identityx` and IdentityX's own wiring build on it. It lives in `httpserver`, not `authz`, because `httpserver` already imports `authz` and owns the writer.
- **Middlewares call `writeMiddlewareError` directly.** The global error hook and `SetupFUN` are gone, and `Boot` calls `validator.SetupValidator`.
- **Real IP is `CF-Connecting-IP`,** or else the peer's IP without its port. Backends run as Cloudflare Containers reached only through their Worker, which forwards the request as is, and Cloudflare's edge overwrites `CF-Connecting-IP` on every proxied request. We checked this on `identityx-api`: requests arrive with `cf-connecting-ip` and `x-real-ip`, and no `x-forwarded-for`. `X-Forwarded-For` isn't read.
- **The rate limit is keyed on that IP,** and buckets idle for 3 minutes are swept.
- **The request ID is logged from the context.** A client-sent ID is kept only if it's 1 to 128 printable ASCII characters. Otherwise a new one is created.
- **The response wrapper passes through `Flush` and `Unwrap`** as well as `Hijack`, so streaming handlers flush through it.
- Metric names, labels and buckets don't change, so dashboards keep working. The status label stays the status text.

## Consequences

- No module in TheTree depends on `github.com/MintzyG/fun` any more. Root `fun` was left only as the error writer's carrier, and that's replaced by a small piece in `lib/go/httpserver/errors.go` (`appError`, `errorCode` and the same code strings, marked `TODO(problem-details)`). The RFC 9457 move (backend wishlist #14) deletes it instead of building on it.
- Trusting `CF-Connecting-IP` only holds while a container is reachable through Cloudflare alone. A backend exposed any other way, through a public port or a tunnel without Cloudflare's proxy, would let clients pick their own rate-limit bucket.
