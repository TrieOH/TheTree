# ADR-0018 — The harness owns its middleware stack

- **Status:** accepted
- **Date:** 2026-10-29
- **Scope:** `lib/go/{httpserver,backend/identityx,authz}`, `api/identityx` (auth wiring), `api/univents` (one test)
- **Amends:** ADR-0016 (`fun/middlewares` and root `fun` stay), ADR-0017 (`SetupFUN`, `fun.AppError` as the carrier)

## Context

After ADR-0017 the only `fun` package still doing work was
`fun/middlewares`: the request stack every Backend runs (real IP, request
ID, access log, metrics, recover, timeout, body limit, rate limit, CORS)
and the JWT / API-key auth primitives. It is about 400 used lines of
mostly stdlib code, reached the writer only through a process-global
`SetErrorWriter` hook, and carried four defects:

- The harness keyed the rate limiter on `r.RemoteAddr`, which keeps the
  port when no proxy header is present: every new connection got a fresh
  bucket.
- The limiter's per-client map never shrank.
- The access log read the request ID from the request header, so an ID
  the middleware minted was logged empty.
- Real IP fell back to the leftmost `X-Forwarded-For`, which is
  client-controlled. (Cloudflare doesn't send it, so in production the
  fallback was only reachable by a client sending the header without
  `CF-Connecting-IP` — which Cloudflare always sets.)

## Decision

- **The stack lives in `lib/httpserver/middleware.go`**, unexported
  except `CORS` (a test asserts the real config) and `RequestIDFromCtx`.
  `rs/cors` and `x/time/rate` stay as the implementations underneath.
- **Auth primitives are `httpserver.Authenticators{JWT, APIKey}.Primitives()`.**
  Each authenticator takes the raw credential and returns the context
  with the identity on it; any error is a 401. `lib/backend/identityx`
  and IdentityX's own wiring build on it. It lives in `httpserver`, not
  `authz`, because `httpserver` already imports `authz` and owns the
  writer.
- **Middlewares call `writeMiddlewareError` directly;** the global error
  hook and `SetupFUN` are gone (`Boot` calls `validator.SetupValidator`).
- **Real IP** is `CF-Connecting-IP`, else the peer's IP without its port.
  The Backends run as Cloudflare Containers reached only through their
  Worker, which forwards the request as is, and Cloudflare's edge
  overwrites `CF-Connecting-IP` on every proxied request (verified on
  `identityx-api`: it arrives with `cf-connecting-ip` and `x-real-ip`,
  no `x-forwarded-for`). `X-Forwarded-For` is not read.
- **Rate limit** keys on that bare IP and sweeps buckets idle for 3
  minutes.
- **Request ID** is logged from the context; a client-sent ID is kept
  only if it is 1–128 printable ASCII characters, else one is minted.
- **Response wrapper** forwards `Flush` and `Unwrap` as well as
  `Hijack`, so streaming handlers flush through it.
- Metric names, labels (status stays the status text) and buckets are
  unchanged, so dashboards keep working.

## Consequences

- No TheTree module depends on `github.com/MintzyG/fun` any more. Root
  `fun` was left only as the error writer's carrier; it is replaced by
  glue in `lib/httpserver/errors.go` (`appError`, `errorCode` and the
  same code strings, marked `TODO(problem-details)`). The RFC 9457 move
  (backend wishlist #14) deletes that glue rather than building on it.
- Trusting `CF-Connecting-IP` holds only while a container is reachable
  solely through Cloudflare. A Backend exposed any other way (a public
  port, a tunnel without Cloudflare's proxy) would let clients choose
  their rate-limit bucket.
