# ADR-0007 — Production deploy surface lives in a standalone `deploy` repo

- **Status:** accepted
- **Date:** 2026-08-18
- **Scope:** repo topology (`TrieOH/TheTree`, `TrieOH/deploy`, `TrieOH/infra`), `compose.prod.yml`, env handling, server operations (`trieoh@main`)

## Context

TheTree was both the source monorepo and the holder of the production runtime
surface: `compose.prod.yml`, the root `.env`, and per-service env files lived
in the repo, and the prod server (`trieoh@main`, Docker Compose, one VPS)
pulled a full TheTree checkout just to run the stack. Three problems followed:

1. **Repo/prod drift.** The committed `compose.prod.yml` referenced
   `git.trieoh.com/trieoh/<svc>:latest`, but the server actually ran pinned
   `v*` tags (and `informd` ran `:latest`). Version bumps happened as silent
   server-side edits, invisible to git.
2. **The server was over-coupled to the source.** Running prod meant a
   TheTree checkout (source, pnpm-lock, node_modules) sitting on the box.
3. **A secrets incident.** `docker compose config` resolves `env_file`
   values into its output; a prod snapshot committed to the new repo leaked
   every live secret. It was scrubbed from history (`git filter-repo` +
   force-push), and the rule "snapshots are never committed" was born.

## Decision

Production runtime moves to a new repo **`TrieOH/deploy`**, checked out at
`~/deploy` on the server. TheTree keeps source + CI + build/publish
(`.dagger/`, `publish.yml`) and no longer carries the prod compose.

Layout and invariants:

- **One folder per project** at the repo root; the current project is
  `thetree/` (`~/deploy/thetree` on the server). The next project adds its
  own folder.
- **`compose.yml` pins `name: thetree`** — the project name must never
  change, or compose orphans `thetree_postgres_data` / `thetree_rustfs_data`
  / `thetree_rustfs_logs` and the `thetree_internal` network (new, empty
  volumes → "postgres looks wiped").
- **Env files are `.<svc>.env` at the project root** (shared `.env` +
  `.identityx.env` / `.univents.env` / `.payssage.env` / `.informd.env`),
  gitignored via `*.env`; committed templates are `.<svc>.env.example` with
  blank values. Per-service files stay separate — keys like `APP_NAME`,
  `APP_URL`, `CORS_ALLOWED_ORIGINS`, `DEBUG_MODE`, `SIMPLE_AUTH_*` collide
  across services with different values.
- **Image tags record what the server runs** (`identityx:v0.35.3`,
  `univents:v0.10.4`, `payssage:v0.7.4`, `informd:latest`). `:latest` is an
  explicit escape hatch only.
- **Prod snapshots are never committed** — `docker compose config` inlines
  all resolved secrets. Snapshots live outside the repo (`~/backups/`).
- **Infra surface (caddy, forgejo, mox, observability, beszel, ntfy) stays
  in `TrieOH/infra`**, its own repo checked out at `~/infra`.

## Consequences

- The server no longer needs a TheTree checkout; `compose.prod.yml` was
  removed from TheTree (git history retains it; rollback of the move =
  redeploy from history or the server `.bak`).
- Deploys are now `cd ~/deploy/thetree && docker compose up -d`; version
  bumps are git commits in deploy, reviewable.
- `AGENTS.md` in TheTree points at `~/deploy/thetree` for prod runtime.
- The Docker embedded-DNS pitfall surfaced by this work (SERVFAIL → project
  down/up or dockerd restart) is documented in the infra repo's README.
- Future automation (deploy workflows, health checks) lives in deploy, not
  TheTree.

## Rejected alternatives

- **Keep prod compose in TheTree** — keeps the drift and the server
  checkout coupling this ADR removes.
- **Fold deploy into `TrieOH/infra`** — infra owns the machine-level
  services; deploy owns the application stack. Different owners, different
  review cadence; one-folder-per-project keeps them separate.
- **Keep `:latest` in the new repo** — contradicts "record what the server
  runs"; pinning the real tags was the point.
