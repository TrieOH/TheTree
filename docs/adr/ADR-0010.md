## Why

The backends were moving off one long-lived VPS onto AWS (Lambda behind API Gateway, Postgres on Neon), and might leave AWS later. IdentityX went first, to learn what the other three would need. Running the old way, as a compose container serving HTTP, had to keep working, and no application code could assume AWS.

A function isn't a server. It's frozen between requests, runs as many copies at once, has no side ports and can be reclaimed at any time. That broke everything IdentityX ran next to its HTTP server: River workers and periodic jobs, the `/riverui` dashboard, the pprof port, Prometheus scraping `/metrics`, an in-memory setup flag, and an in-memory rate limiter used as the global limit.

## Decision

- **One image, two modes,** picked by `RUNTIME_MODE=hosted|managed` in `lib/config.Server`. Hosted is the long-lived server. Managed runs the same binary behind the Lambda Web Adapter as two functions, picked by `RUNTIME_ROLE`: `api` behind the gateway, and `worker`, fed by the job queue and the scheduler through the adapter's `/events` route. `/events` is mounted only on the worker, so the gateway can never reach it.
- **Every outside service is an interface,** with one adapter per provider, picked when wiring by the mode or an env var:
  - Background jobs, `lib/jobs` (`Enqueuer`, `Registry`, `Envelope`): an in-process worker pool and tickers in hosted mode; SQS with per-message failure reports, plus EventBridge Scheduler calling the worker, in managed mode. Periodic jobs are declared once in `jobs.Periodic`, and `identityx schedules` prints them for the deploy. River is gone from IdentityX, with its tables left in place.
  - Email, `lib/email.Sender`: SMTP or SES, picked by `EMAIL_TRANSPORT`. Hosted keeps SMTP and mailpit.
  - Secrets, `lib/secrets.Source`: the environment as is, or AWS Secrets Manager, picked by `SECRETS_PROVIDER`. It only fills the environment before config is parsed, and an env var that's already set wins, so config never knows where a value came from. `just inject <svc>` fills the store.
- **Telemetry is pushed, never scraped.** Traces, metrics (the Prometheus collectors bridged to OTLP) and logs (zap teed to OTLP) go to the standard `OTEL_EXPORTER_OTLP_*_ENDPOINT`s. `/metrics` is removed. `Boot` stops cleanly on SIGTERM so the last batch is sent.
- **Nothing trusts in-process state across copies.** Whether setup is done is a database check, cached once true. The rate limit is configurable (`RATE_LIMIT_RPS`, `RATE_LIMIT_BURST`, `DISABLE_RATE_LIMIT`) and is only a per-copy backstop. In managed mode, the gateway's throttling is the real limit.
- **Connections are pooled.** The API connects through a transaction-mode pooler: Neon's pooled endpoint in production, pgbouncer (`identityx-pooler`) locally. Migrations use the direct endpoint and run outside the process.
- **Floci stands in for AWS locally** (`just identityx managed`). Infrastructure as code for real AWS waits until managed mode fully works.

## Consequences

- Hosted jobs live in memory, so jobs queued when the process dies are lost. River kept them. Managed mode has SQS with a dead-letter queue.
- A managed cold start runs `keys.EnsureAll` over every project, so boot gets slower as projects grow.
- The observability stack must accept OTLP metrics and logs before this ships. The other backends lose `/metrics` too, since the harness is shared.
- The other backends move to the same interfaces one at a time. `lib/river` stays until they do.

## Changes

- **2026-10-19:** replaced by ADR-0011. Every piece of this was AWS-only, so we moved to Cloudflare Containers instead.
