# ADR-0010 — Hosted and managed runtime modes behind provider-neutral seams

- **Status:** accepted
- **Date:** 2026-10-08
- **Scope:** `lib/go/{config,httpserver,telemetry,jobs,email,secrets}`, `api/identityx`, `compose.yml`, `justfile`, `tools/floci`

## Context

The Backends move from one long-lived VPS stack to AWS (Lambda behind API
Gateway, Neon for Postgres), and may move off AWS again later. IdentityX goes
first, to measure what the other three will need. The old way of running —
a compose container serving HTTP — must keep working, and nothing in the
application may assume AWS.

A function is not a server: it is frozen between requests, can run as many
instances at once, has no side ports, and is reclaimed at will. That breaks
everything IdentityX ran in-process next to its HTTP server: River workers
and periodic jobs, the `/riverui` dashboard, the pprof port, Prometheus
scraping `/metrics`, an in-memory setup flag, and an in-memory rate limiter
treated as the global limit.

## Decision

- **One image, two runtime modes** (`RUNTIME_MODE=hosted|managed`, in
  `lib/config.Server`). Hosted is the long-lived server. Managed runs the
  same binary behind the Lambda Web Adapter, as two functions selected by
  `RUNTIME_ROLE`: `api` (behind the gateway) and `worker` (fed by the job
  queue and the scheduler through the adapter's `/events` pass-through,
  mounted only on the worker so the gateway can never reach it).
- **Every external dependency is an interface with per-provider adapters;**
  the mode or an env var picks the adapter at wiring time:
  - background work — `lib/jobs` (`Enqueuer`, `Registry`, `Envelope`):
    `inprocess` (worker pool + tickers) in hosted, `sqsjobs` +
    `lambdaevents` (SQS with per-message failure reporting, EventBridge
    Scheduler invoking the worker) in managed. Periodic jobs are declared
    once (`jobs.Periodic`); `identityx schedules` prints them for the
    deploy. **River is gone from IdentityX** (its tables are left in place).
  - email — `lib/email.Sender`: SMTP (`Client`) or SES (`email/ses`), by
    `EMAIL_TRANSPORT`. Hosted keeps SMTP/mailpit.
  - secrets — `lib/secrets.Source`: `Env` (no-op; compose env_file) or AWS
    Secrets Manager (`secrets/awssm`), by `SECRETS_PROVIDER`. The source
    only fills the environment before config parsing, explicit env wins, so
    config structs never learn where values came from. `just inject <svc>`
    seeds the store.
- **Telemetry is pushed, never scraped:** traces, metrics (the existing
  Prometheus collectors bridged into OTLP) and logs (zap teed into OTLP) go
  to the standard `OTEL_EXPORTER_OTLP_*_ENDPOINT`s. `/metrics` is removed.
  `Boot` stops gracefully on SIGTERM so the last batch is flushed.
- **Process-local state is not trusted across instances:** the setup state
  is a database check (cached once true); the rate limit is configurable
  (`RATE_LIMIT_RPS`/`_BURST`, `DISABLE_RATE_LIMIT`) and is a per-instance
  backstop — the gateway's throttling is the global limit in managed mode.
- **Pooled connections everywhere:** the API connects through a
  transaction-mode pooler (Neon's pooled endpoint; `identityx-pooler`
  pgbouncer locally) with a configurable pool size; migrations use the
  direct endpoint and stay out of the process.
- **Floci is the local AWS** for managed mode (`just identityx managed`).
  Infrastructure-as-code for real AWS waits until managed mode runs fully.

## Consequences

- Hosted jobs live in memory: work queued when the process dies is lost
  (River persisted it). Accepted for hosted; managed has SQS with a DLQ.
- A managed cold start runs `keys.EnsureAll` over every project, so boot
  time grows with the project count.
- The observability stack must accept OTLP for metrics and logs before a
  release with this change ships; the other three Backends lose `/metrics`
  too, since the Harness is shared.
- The other Backends adopt the same seams one at a time; `lib/river` stays
  until they do.
