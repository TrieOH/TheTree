## Why

The backends used the root `fun` package for errors and error responses, and its errors are HTTP errors. A repo returned `fun.ErrNotFound`, a service returned `fun.ErrBadRequest("…")`, and callers checked status codes, with `fun.Is(err, fun.CodeNotFound)` about 190 times. That caused problems:

- **The domain spoke HTTP.** Whether "user not found" is a 404, or a 401 at login, was decided wherever the error was built, not where the response was written. Services re-wrapped repo errors just to change the status.
- **Errors had no names.** A test or caller could ask "was it a 400?", not "was it *users can't add themselves*?". Two failures with the same code could only be told apart by comparing strings.
- **Internal errors were marked by hand.** About 80 places built `ErrInternal(…)` or `Errf(…).Internal()`, usually with `%v`, which drops the cause.
- **Raw errors reached clients.** No error mapper was registered, so `fun.Error` sent the raw `err.Error()` of anything unmapped, and DBE sent `pgErr.Error()` for unknown constraints and codes.
- **Every 4xx marked its span as an error,** so dashboards counted user mistakes as failures.

We're heading to `fun/problems` (RFC 9457), which maps any Go error through `ErrorMapper`s. For that switch to be just a mapper swap, the code returning errors has to stop knowing about HTTP first.

## Decision

- **Our code stops importing root `fun`,** except `lib/go/httpserver`, which writes the response. `fun/middlewares` and `fun/handlers` stay, and since they use root `fun` inside, so does `SetupFUN` for the responses they write. Their auth middleware answers any auth hook error with a 401 and its message, so the hook errors in `lib/go/backend/identityx` (`ErrEmailNotVerified`, `ErrInvalidAPIKey` and so on) are plain sentinels that never reach the map. `fun/bind` goes, since only `bind.SetValidator` was called. `fun.From(r)`, used by the MercadoPago signature check, becomes `r.Header` and `r.URL.Query()`.

- **Errors have names and live in a leaf package.** Each backend has `api/<svc>/errs`, one file per area, importing only the standard library (and `uuid` for typed errors). Repos, services, authz, jobs, handlers and the mapper all import it. We don't declare errors next to the code that first returns them, because another layer that needs `errors.Is` on them would import the feature and risk an import cycle.

  ```go
  // api/identityx/errs/projects.go
  var (
      ErrAddSelf  = errors.New("users can't add themselves to projects")
      ErrAddOwner = errors.New("owners can't be added to projects they own")
  )

  // api/univents/errs/checkouts.go
  type OutOfStockError struct{ ItemIDs []uuid.UUID }
  ```

  A sentinel's text is the message the client sees. Errors that carry data are typed errors. Errors every backend shares (`database.ErrNotFound`, the constraint classes, `authz.ErrInsufficientRole`, `validator.Error`, the SDK's `idx.ErrNoIdentity`) live in `lib/go` and `sdk/go/IdentityX`. An error about specific request fields carries them with `lib/fielderr` (`fielderr.On(errs.ErrNoItems, "items", "min=1")`), and the writer lists them in the response.

- **Code returns, wraps and matches errors. It never picks a status.**

  ```go
  // before
  return fun.ErrBadRequest("users can't add themselves to projects")
  return fun.Errf("checkout: enqueue expiry: %v", err).Internal()
  if fun.Is(err, fun.CodeNotFound) { … }

  // after
  return errs.ErrAddSelf
  return fmt.Errorf("checkout: enqueue expiry: %w", err)
  if errors.Is(err, database.ErrNotFound) { … }
  ```

  An error without a name is internal. Nothing has to mark it.

- **DBE keeps its shape and returns named errors.** Repo calls stay `return nil, repo.dbe(err)`.

  ```go
  // repo constructor: the resource's not-found error instead of a string
  dbe: database.NewErrorHandler(errs.ErrActorNotFound),
  // the override takes an error too
  repo.dbe(err, errs.ErrMemberNotFound)

  // app/constraints.go: constraints map to errors, not messages
  "uniq_projects_slug": errs.ErrProjectSlugTaken,
  ```

  `pgx.ErrNoRows` becomes the resource's not-found error joined with `database.ErrNotFound`. A registered constraint becomes its named error joined with its class (`ErrUniqueViolation`, `ErrForeignKeyViolation`, `ErrCheckViolation`), so `errors.Is` works for both. An unregistered constraint becomes its class alone, carrying the constraint name. Any other error passes through as is. `BatchExec` returns a `BatchError` naming each failed item by ID instead of one validation message.

- **HTTP lives in one mapper per backend.** `internal/app` holds a table from named error to status and code. `lib/go/httpserver` holds the shared entries (database errors and classes, validation) and the writer. The mapper walks the error chain from the outside in, and the first link found in the table wins, so the most specific error decides. A login's `ErrInvalidCredentials` wrapping `database.ErrNotFound` is a 401, not a 404. The client gets the matched error's own message, never the `%w` context around it. Anything unmapped is a plain 500, with its cause sent to logs and the span, not the body. A missing row is a 404 that reads as its resource's error even without a table line. The table is installed as fun's `AppErrorMapper`, so error bodies from the fun middlewares and from the strict handlers go through the same table. Authz writes scope rejections through `httpserver.WriteError`, passed in `authz.Options.WriteError`, because authz can't import the writer that maps its own errors.

- **The response shape stays.** The writer sends the same `{code, message, error: {code, message, fields}, timestamp, module}` that `fun` writes today, so the front, the spec and the fun middlewares' bodies stay one format. Codes match as closely as the table allows, and small differences are fine because nothing is live yet. Removing this envelope is a later change.

- **Only a 5xx marks a span as an error.** `TraceMiddleware` records every returned error but only sets the error status when the mapper says 5xx.

## Consequences

- Moving to `fun/problems` means replacing the mapper: each table entry becomes an `fp.Problem`, the table an `fp.ErrorMapper`, the writer `fp.FromError`. No repo, service or handler changes.
- Every new error a client can see is a line in `errs` and a line in the mapper. A forgotten mapper line gives a 500, not a wrong 4xx. Each backend's tests check that every constraint's error has its own line.
- Tests check the failure they mean (`errors.Is(err, errs.ErrAddSelf)`) instead of a status.
- Unmapped errors and unregistered constraints no longer leak driver or internal text to clients.
- `sdk/go/IdentityX` returns its own sentinels instead of `fun.ErrUnauthorized`. Its only users are our backends.
- Root `fun` stays in `go.mod`, pulled in by `fun/middlewares` and `fun/handlers`, and used directly in `lib/go` by the writer. `fun/bind` is gone.

## Changes

- ADR-0017 removed the envelope, ADR-0018 removed the last `fun` dependency, ADR-0019 replaced the table with RFC 9457 problems declared in the spec, and ADR-0022 generates most sentinels from those declarations.
