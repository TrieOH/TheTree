# ADR-0016 — Errors are named Go errors, HTTP lives in one mapper

- **Status:** proposed
- **Date:** 2026-10-25
- **Scope:** `lib/go/{database,httpserver,validator,backend/identityx}`, `sdk/go/IdentityX`, `api/{identityx,informd,payssage,univents}`

## Context

The Backends use the root `fun` package for two things: errors and error
responses. Its errors are HTTP errors. A repo returns `fun.ErrNotFound`, a
service returns `fun.ErrBadRequest("…")`, and callers branch on HTTP codes
(`fun.Is(err, fun.CodeNotFound)`, about 190 times). So:

- **The domain speaks HTTP.** Whether "user not found" is a 404 or a 401
  (login) is decided wherever the error is built, not where the response
  is written. Services re-wrap repo errors only to change their status.
- **Errors have no names.** A test or a caller can ask "was it a 400?",
  not "was it `users can't add themselves`?". Two different failures with
  the same code are indistinguishable without comparing strings.
- **Internal errors are classified by hand.** About 80 sites build
  `ErrInternal(…)` or `Errf(…).Internal()`, usually with `%v`, which drops
  the cause chain.
- **Raw errors reach clients.** No `AppErrorMapper` is registered, so
  `fun.Error` sends the raw `err.Error()` of any unmapped error, and DBE
  sends `pgErr.Error()` for unregistered constraints and unknown codes.
- **Every 4xx marks its span as an error** (`TraceMiddleware`), so
  dashboards count user errors as failures.

`fun/problems` (RFC 9457, `fp.FromError(err, mappers...)`) is where error
responses are going. It maps arbitrary Go errors through `ErrorMapper`s, so
the code that returns errors must stop knowing about HTTP before the switch
can be a mapper swap.

## Decision

- **TheTree code stops importing root `fun`.** `fun/middlewares` and
  `fun/handlers` stay; they use root `fun` internally, so `SetupFUN`
  (`SetConfig`, the interceptor, `SetPathParamFunc`) stays for the
  responses they write. `fun/bind` goes: only `bind.SetValidator` is
  called, and nothing binds through it. `fun.From(r)` (MercadoPago's
  signature check) becomes `r.Header` / `r.URL.Query()`.

- **Errors are named, and they live in a leaf package.** Each Backend has
  `api/<svc>/errs`, one file per area, importing only the standard library
  (and `uuid` for typed errors). Repos, services, authz, jobs, handlers and
  the mapper all import it; declaring errors next to the code that first
  returns them is out, because a layer above or below that needs
  `errors.Is` on them would import the feature and risk a cycle.

  ```go
  // api/identityx/errs/projects.go
  var (
      ErrAddSelf  = errors.New("users can't add themselves to projects")
      ErrAddOwner = errors.New("owners can't be added to projects they own")
  )

  // api/univents/errs/checkouts.go
  type OutOfStockError struct{ ItemIDs []uuid.UUID }
  ```

  The text of a sentinel is its client-facing message. Errors that carry
  data are typed errors. Errors shared by every Backend
  (`database.ErrNotFound`, the constraint classes, the validation error
  with its fields) live in `lib/go`.

- **Code returns, wraps and matches; it never classifies.**

  ```go
  // before
  return fun.ErrBadRequest("users can't add themselves to projects")
  return fun.Errf("checkout: enqueue expiry: %v", err).Internal()
  if fun.Is(err, fun.CodeNotFound) { … }

  // after
  return errs.ErrAddSelf
  return fmt.Errorf("checkout: enqueue expiry: %w", err)
  if errors.Is(err, database.ErrNotFound) { … }
  ```

  An error that is not named is internal; nothing marks it as such.

- **DBE keeps its shape and returns named errors.** Repo call sites stay
  `return nil, repo.dbe(err)`.

  ```go
  // repo constructor: the resource's not-found error instead of a string
  dbe: database.NewErrorHandler(errs.ErrActorNotFound),
  // the override takes an error too
  repo.dbe(err, errs.ErrMemberNotFound)

  // app/constraints.go: the registry maps constraints to errors, not messages
  "uniq_projects_slug": errs.ErrProjectSlugTaken,
  ```

  `pgx.ErrNoRows` becomes the resource's not-found error joined with
  `database.ErrNotFound`. A registered constraint becomes its named error
  joined with its class (`ErrUniqueViolation`, `ErrForeignKeyViolation`,
  `ErrCheckViolation`), so `errors.Is` holds for both. An unregistered
  constraint becomes its class alone, carrying the constraint name. Any
  other error passes through unchanged. `BatchExec` returns the per-item
  errors joined instead of one validation message.

- **HTTP lives in one mapper per Backend.** `internal/app` holds a table
  from named error to status and wire code; `lib/go/httpserver` holds the
  shared entries (the database errors and classes, the validation error)
  and the writer. The mapper walks the error chain from the outermost link
  inward and the first link in the table wins, so the most specific error
  maps (a login's `ErrInvalidCredentials` wrapping `database.ErrNotFound`
  is a 401, not a 404). The client gets the matched link's own message,
  never the `%w` context around it. Anything unmapped is a generic 500
  whose cause goes to logs and the span, not the body.

- **The envelope stays.** The writer emits the same
  `{code, message, error: {code, message, fields}, timestamp, module}`
  shape `fun` writes today, so the front, the spec and the error bodies
  the `fun` middlewares write stay one format. Wire codes are matched as
  closely as the table allows; small differences are accepted (nothing is
  live). Removing the envelope is a later change.

- **Only 5xx marks a span as an error.** `TraceMiddleware` records every
  returned error but sets the error status only when the mapper says 5xx.

## Consequences

- Moving to `fun/problems` is replacing the mapper: each table entry
  becomes an `fp.Problem`, the table an `fp.ErrorMapper`, the writer
  `fp.FromError`. No repo, service or handler changes.
- Every new user-facing error is a line in `errs` and a line in the
  mapper. A forgotten mapper line is a 500, not a wrong 4xx.
- Tests assert the failure they mean
  (`errors.Is(err, errs.ErrAddSelf)`) instead of its status.
- Unmapped errors and unregistered constraints no longer leak driver or
  internal text to clients.
- `sdk/go/IdentityX` returns its own sentinels instead of
  `fun.ErrUnauthorized`; its only consumers are our Backends.
- Root `fun` stays in `go.mod` transitively through `fun/middlewares` and
  `fun/handlers`.
