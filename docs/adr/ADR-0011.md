# ADR-0011 — Backends run on Cloudflare Containers; jobs over HTTP (supersedes ADR-0010)

- **Status:** accepted
- **Date:** 2026-10-19
- **Scope:** `lib/go/{config,jobs,email,secrets}`, `api/identityx`, `compose.yml`, `justfile`, `tools/floci`

## Context

ADR-0010 moved IdentityX onto AWS (Lambda behind API Gateway, SQS,
EventBridge Scheduler, SES, Secrets Manager) behind provider-neutral seams.
Every one of those pieces is AWS-only, and the deploy would have bound us to
the AWS ecosystem. The fronts already ship on Cloudflare Workers, and
Cloudflare Containers run an ordinary Docker image as a real process, so the
Backends can live next to them without the Lambda-shaped compromises.

## Decision

- **One runtime, no mode switch.** `RUNTIME_MODE`/`RUNTIME_ROLE`, the Lambda
  Web Adapter, `identityx schedules`, the SQS carrier, the SES and Secrets
  Manager adapters, the `lib/secrets` seam, `just inject` and Floci are gone.
  The image is a plain HTTP server, in compose and on Cloudflare alike.
- **Deploy:** a Worker per Backend (`api/<svc>/cloudflare`) fronts a
  Cloudflare Container built from the service's Dockerfile. Containers
  sleep when idle and the Worker spreads requests over a few instances.
  Postgres stays on Neon (pooled endpoint).
- **Config is the environment.** Wrangler vars and secrets are passed to
  the container as environment variables; config structs are unchanged.
- **Background jobs over HTTP** (`lib/jobs/httpjobs`), picked by `JOBS_URL`:
  - unset (local compose): the `inprocess` runner, as before.
  - set (Cloudflare): `Enqueue` POSTs the `jobs.Envelope` to `JOBS_URL`.
    The Worker intercepts that host (`outboundByHost`) and sends the
    envelope to a Cloudflare Queue; the queue consumer POSTs it to the
    container's `/events` (2xx done, 4xx dropped, 5xx retried, then the
    dead-letter queue). Cron Triggers enqueue the periodic jobs; their
    crons mirror `jobs.Periodic`.
  - `/events` is outside the spec and auth chains; the Worker refuses it on
    public requests, and the container is reachable only through the Worker.
- **Email is SMTP only**, through any relay.

## Consequences

- Go code has no Cloudflare dependency: the coupling is the Worker, the
  Wrangler config and the Envelope-over-HTTP contract, all replaceable by
  any queue that can POST JSON.
- Periodic cadences are declared twice (`jobs.Periodic` and the Worker's
  crons) and must be kept in step.
- Multiple instances each hold their own rate-limit bucket and pool, as in
  ADR-0010's managed mode; the process-local-state rules there still hold.
- The other Backends adopt the same shape one at a time; `lib/river` stays
  until they do.
