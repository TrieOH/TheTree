## Why

ADR-0010 moved IdentityX onto AWS: Lambda behind API Gateway, SQS, EventBridge Scheduler, SES and Secrets Manager. Every one of those is AWS-only, so deploying it would have tied us to AWS. Our fronts already run on Cloudflare Workers, and Cloudflare Containers run a normal Docker image as a real process. The backends can live next to the fronts without bending into Lambda's shape.

## Decision

- **One way to run.** `RUNTIME_MODE`, `RUNTIME_ROLE`, the Lambda Web Adapter, `identityx schedules`, the SQS, SES and Secrets Manager adapters, the `lib/secrets` interface, `just inject` and Floci are all removed. The image is a plain HTTP server, in compose and on Cloudflare.
- **Deploy.** Each backend has a Worker (`api/<svc>/cloudflare`) in front of a Cloudflare Container built from its Dockerfile. Containers sleep when idle, and the Worker spreads requests over a few copies. Postgres stays on Neon, through the pooled endpoint.
- **Config is the environment.** Wrangler vars and secrets reach the container as env vars, and the config structs don't change.
- **Background jobs go over HTTP** (`lib/jobs/httpjobs`), depending on `JOBS_URL`:
  - Unset, as in local compose: the in-process runner, as before.
  - Set, as on Cloudflare: `Enqueue` POSTs the `jobs.Envelope` to `JOBS_URL`. The Worker catches that host (`outboundByHost`) and puts the envelope on a Cloudflare Queue. The queue consumer POSTs it to the container's `/events`. A 2xx means done, a 4xx drops the job, a 5xx retries it and finally sends it to the dead-letter queue. Cron Triggers enqueue the periodic jobs, with crons that mirror `jobs.Periodic`.
  - `/events` is outside the spec and the auth chains. The Worker refuses it on public requests, and the container is only reachable through the Worker.
- **Email is SMTP only,** through any relay.

## Consequences

- The Go code doesn't depend on Cloudflare. The only ties are the Worker, the Wrangler config and the envelope-over-HTTP contract, and any queue that can POST JSON could replace them.
- Periodic schedules are written twice, in `jobs.Periodic` and in the Worker's crons, and must be kept in step.
- Each copy of a container has its own rate-limit bucket and connection pool, so ADR-0010's rules about in-process state still hold.
- The other backends move to this one at a time. `lib/river` stays until they do.
