## Why

Auth matched routes to their checks by operation ID strings, and that failed silently in three ways.

1. **Casing.** oapi-codegen passes PascalCase IDs to the middleware, but the resolver stored camelCase ones from the spec. Every backend lowercased the first letter at runtime to bridge them. If any step got it wrong, the lookup found no checks, which looked exactly like a public route. A protected route could become public with no error.
2. **Hand-written lists.** `clientOnlyOps` (33 entries in IdentityX) and `SkipSetupGuard` were never checked against the spec. A typo or a renamed operation dropped its guard.
3. **A test that couldn't fail.** The parity test built its expected list from the same `clientOnlyOps` it checked, so a missing operation was never caught.

ADR-0001 also promised that `CreateRouter` would shrink to a small `Routes` callback. It didn't. The strict-server glue (auth dispatch, validation, error mapping) was identical across the four backends, about 500 lines of code and 1,600 of tests.

## Decision

**Auth fails closed.** In `lib/go/authz`:

- `NewResolver` stores checks under the generated, PascalCase ID (`GeneratedOperationID`: `listActors` becomes `ListActors`), the exact value the generated server passes. No string fixing at request time.
- `Options` gains `ClientOnly` and `ClientOnlyOps`. `ClientOnlyOps` and `SkipSetupGuard` are checked against the spec when the resolver is built, so an unknown operation stops the boot. `ClientOnlyOps` without a `ClientOnly` middleware stops it too.
- A lookup that finds nothing at request time returns 500. An empty list of checks still means public, on purpose.

**The glue moves to the harness.** `lib/go/httpserver` gains `strict.go` with `AuthDispatch`, `ValidateMiddleware`, `StrictRequestErrorHandler` and `StrictResponseErrorHandler`. Each backend keeps a 7-line `adapt` cast and a 25-line `mountStrict`, because those touch its own generated types. The shared tests move to `lib/go/httpserver`.

**SDK bootstrap.** `sdk/identityx` gains `MustBootstrap`, which panics on failure. Each backend's config gains `ToIdentityXConfig()`, so `SetupIdentityX` becomes one line.

## Consequences

- A renamed operation or a typo in a list now stops the boot instead of exposing a route.
- Auth dispatch and validation live in one place. A change to them is one file again.
- What's left per backend is type conversions and param-error mapping, with no logic of its own.
- An unknown operation ID used to fall through as public. It now gets a 500.

## Rejected

- **An `x-client-only` spec extension.** It needed a parser change at the time. A list checked at boot gives the same guarantee. (ADR-0005 later did this with `x-scope`.)
- **A separate `lib/oapi` package.** Nothing uses it without `lib/go/httpserver`, for the same reason ADR-0001 kept the router in it.
- **Generic param-error mapping in the lib.** The generated error types only have plain fields, so it would need reflection on type names. A 13-line switch per backend was cheaper. (ADR-0009 later changed this once the copies drifted.)
