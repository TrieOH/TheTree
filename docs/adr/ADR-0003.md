# ADR-0003 — Fail-closed auth resolution + strict-server glue in the harness

- **Status:** accepted
- **Date:** 2026-08-01
- **Scope:** `lib/go/authz`, `lib/go/httpserver`, `api/{identityx,informd,payssage,univents}/internal/app`, `sdk/go/IdentityX`

## Context

The auth dispatch chain had three silent failure modes, all rooted in
stringly-typed operation identities:

1. **Casing hack.** oapi-codegen passes operationIDs to strict middlewares in
   generated (PascalCase) form, while the resolver keyed chains by spec-form
   (camelCase) IDs. Every backend re-implemented a runtime
   `strings.ToLower(first-letter)` bridge; a mismatch at any link meant an
   empty-chain lookup, which was indistinguishable from a public operation —
   protected routes became public with no error anywhere.
2. **Unvalidated hand lists.** `clientOnlyOps` (identityx, 33 entries) and
   `SkipSetupGuard` were appended/looked-up after resolver construction. A
   typo or a renamed spec operationId silently dropped the guard.
3. **Circular test.** The parity test derived its expectation from the same
   `clientOnlyOps` variable it asserted against, so an omitted operation
   could never be detected.

Separately, ADR-0001's promise that `CreateRouter` would become a thin
`Routes` closure was unmet: the strict-server glue (auth-dispatch loop,
validation middleware, fun error mapping) was byte-identical across the four
backends (~500 production lines + ~1600 test lines), so an auth-seam change
was still a 4× edit.

## Decision

**Fail-closed resolution.** `lib/authz`:

- `NewResolver` keys chains by **generated-form** operationID
  (`GeneratedOperationID`: spec `listActors` → `ListActors`, the exact value
  the generated server passes). The dispatch does an exact lookup with no
  string surgery.
- `Options` gains `ClientOnly` + `ClientOnlyOps`; `SkipSetupGuard` and
  `ClientOnlyOps` are validated against the spec at construction — an
  unknown operationId fails startup. `ClientOnlyOps` without a `ClientOnly`
  middleware also fails startup.
- A lookup miss in the dispatch (spec/codegen drift) returns 500; empty
  chain still means public by design.

**Strict glue in the harness.** `lib/httpserver` gains `strict.go`:
`AuthDispatch` (the dispatch loop), `ValidateMiddleware` (reflection body
validation), `StrictRequestErrorHandler` / `StrictResponseErrorHandler`
(fun envelopes). The generated strict types are distinct named types with
identical underlying shapes, so each backend keeps a ~7-line `adapt`
conversion and its `mountStrict` (~25 lines, the generated-type
`NewStrictHandlerWithOptions` call and the param-binding error mapping, which
touches generated error types). The generic dispatch/validation test suites
moved to `lib/httpserver`; per-backend copies were deleted.

**SDK bootstrap.** `sdk/identityx` gains `MustBootstrap` (Bootstrap that
panics — boot-time fatality). Each backend's `config.Config` gains
`ToIdentityXConfig()`; `SetupIdentityX` wrappers shrink to one line.

## Consequences

- A spec rename or a hand-list typo is now a boot failure, not a silent
  exposure. The auth dispatch loop and validation live in exactly one place;
  a harness change is a one-file edit again.
- The generated types are the seam: per-backend code is a thin adapter
  (conversions + spec registry + param-error mapping) — no behavior logic.
- Behavior change (accepted): dispatch now fails closed (500) on unknown
  operationIDs, which previously fell through as public.

## Rejected alternatives

- **OpenAPI extension (`x-client-only`) for the scope list** — the spec
  cannot express per-operation scope requirements without a parser change;
  the boot-validated Options list gives the same fail-fast guarantee with
  no spec churn.
- **Splitting the glue into a new `lib/oapi`** — no caller needs it without
  `lib/httpserver`; same reasoning as ADR-0001's rejection of a separate
  router module.
- **Generic/reflection-based param-error mapping in lib** — the generated
  error types carry plain fields (not methods), so the mapping cannot be
  expressed generically without reflection over type names; the ~13-line
  per-backend switch is the honest cost of touching generated types.
