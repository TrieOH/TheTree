# ADR-0002 — Feature modules expose one Operations seam (codegen-forward)

- **Status:** accepted
- **Date:** 2026-08-01
- **Scope:** `api/{identityx,informd,payssage,univents}/internal/features/*`

## Context

Every feature shipped as a quad of subpackages — `commands/`, `handlers/`,
`queries/`, `repos/` — plus a facade file re-exporting all four. The facade
was pure aliases (deletion test: nothing reappears), and the `queries`
subpackage was ~100% pass-through (identity resolution + authz guard + one
repo call). Understanding one concept meant bouncing across four packages;
adding a feature meant rewiring four structs in `wire.go`.

A hand-written OpenAPI spec exists (`api/identityx/api-spec.yml`), and the
outward interface is planned to be generated from OpenAPI schemas. The HTTP
binding layer (handlers) will therefore be replaced by generated code.

## Decision

Collapse the upper three layers per feature into **one package per feature**
(`features/<x>`) exposing a single operations seam:

- `features/<x>/operations.go` — `Operations` struct + `NewOperations(...)`;
  deps are the union of the old commands and queries repo sets.
- Command and query method files move to the feature root (identical method
  signatures; receiver `o`). `commands/`, `queries/`, and the facade file are
  deleted.
- `handlers/` and `repos/` **stay as subpackages**: handlers are the
  sacrificial HTTP binding that OpenAPI codegen replaces; repos are the
  persistence adapters injected cross-feature through `ports/`.
- `wire.go` merges its `queries` and `commands` structs into one
  `operations` struct; `initQueries` + `initCommands` become
  `initOperations`. Routers import `features/<x>/handlers` directly for
  `RegisterRoutes`.

The `Operations` struct is the target codegen will call into: generated HTTP
binding takes `ctx + typed payload → models` from one module per feature.

## Consequences

- 36 features collapsed (identityx 11, informd 7, payssage 11, univents 7
  + the new `badges` feature); ~3 packages per feature deleted.
- `wire.go` per backend: two structs and two init funcs gone; handler
  constructors take one `ops` argument instead of `(commands, queries)`.
- Existing tests moved with the merge (univents `events/commands` → the
  feature root); they now cross the same seam codegen will use.
- Authz guards moved with their methods; they remain scattered until the
  authorize module (ADR to follow) absorbs them.
- **Pre-existing breakage fixed:** the `badges` feature merged without its
  sqlc-generated code; `sqlc generate` was re-run for univents.

## Rejected alternatives

- **Full internalization (repos inside the feature package)** — repos are
  injected cross-feature through `ports.*Repo` interfaces, so they must stay
  importable; internalizing would contort `wire.go`.
- **Absorbing handlers now** — they are the next layer to be replaced by
  OpenAPI codegen; hand-rewriting them into the feature module is throwaway
  work.
- **Waiting for the OpenAPI tooling** — the operations merge is orthogonal:
  generated handlers call the operations either way. Collapsing now gives
  codegen one stable target per feature instead of a four-package pile.
- **Keeping the `Commands` name for the merged struct** — it now holds every
  read too; `Operations` names the seam for generated-code readers.
