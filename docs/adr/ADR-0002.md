## Why

Every feature was split into `commands/`, `handlers/`, `queries/` and `repos/`, plus a facade file that only re-exported the four. The `queries` package did almost nothing: find the caller, check access, call the repo. Reading one feature meant jumping across four packages, and adding one meant wiring four structs in `wire.go`.

We also planned to generate the HTTP handlers from the OpenAPI spec, so the handler layer was going to be replaced anyway.

## Decision

Each feature becomes one package, `features/<x>`, with one entry point:

- `operations.go` holds the `Operations` struct and `NewOperations(...)`. Its dependencies are the old commands' and queries' repos combined.
- The command and query methods move to the feature root with the same signatures. `commands/`, `queries/` and the facade are deleted.
- `handlers/` and `repos/` stay as subpackages. Handlers are what codegen will replace. Repos are injected into other features through `ports/`, so they must stay importable.
- `wire.go` merges its `queries` and `commands` structs into one `operations` struct, and `initQueries` plus `initCommands` into `initOperations`.

Generated handlers will call `Operations`: a context and a typed payload in, models out.

## Consequences

- 36 features merged (IdentityX 11, Informd 7, Payssage 11, Univents 7, plus the new `badges`), about three packages deleted per feature.
- Handler constructors take one `ops` argument instead of `(commands, queries)`.
- Tests moved with their code and now go through the same entry point codegen will use.
- Access checks moved with their methods. They stay scattered until a shared authorization module takes them.
- The `badges` feature had been merged without its sqlc code. `sqlc generate` was rerun for Univents.

## Rejected

- **Move repos into the feature package.** Other features inject them through `ports`, so they have to stay importable.
- **Merge handlers too.** Codegen replaces them next, so rewriting them by hand is wasted work.
- **Wait for the OpenAPI tooling.** Generated handlers call the operations either way, and one stable target per feature makes codegen easier.
- **Keep the name `Commands`.** The struct holds every read as well, so `Operations` is the honest name.

## Changes

- ADR-0015 later moved repos and handlers into the feature package too.
