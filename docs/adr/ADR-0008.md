# ADR-0008 — Boot: the Harness owns the process lifecycle

- **Status:** accepted
- **Date:** 2026-09-18
- **Scope:** `lib/go/httpserver`, `lib/go/database`, `api/{identityx,informd,payssage,univents}/internal/app`

## Context

Every backend's `Start()` hand-encoded the same ~15-step boot skeleton
(constraint registry → config → FUN → clients → `SetupDB` → tracer →
runner → river → serve), so init ordering lived in four heads instead of
one module. Four hidden "call this before X" contracts enforced by
convention only:

1. `SetupFUN` before any request is handled;
2. the constraint registry (`SetConstraintErrorRegistry`) before
   `SetupDB`'s `validateConstraints` reads it;
3. `SetDefaultRunner` before the first `RunTx`;
4. tracer init before spans are meaningful — inconsistently placed even
   relative to the DB connect, so connect spans were dropped today.

River migration placement had already drifted (in-app in payssage,
in-wire in identityx/univents, absent in informd). The app was a
package-global singleton (`var app Informd`) mutated by `Start()`, so the
real wire-up was testable only by booting a whole process. And each
backend's boot baked in Postgres, so a future Backend on a different store
would have had to fork the skeleton.

## Decision

- **`httpserver.Boot(cfg Config, start StartFunc) error`** — the Harness
  deepens from HTTP-serving to process lifecycle. Boot owns the sequence:
  FUN runtime → tracer → the backend's components (via `start`) → serving
  → shutdown in reverse order (the backend's shutdown before the tracer,
  so spans from stopping workers are kept). Tracer init now happens before
  the store opens, so connect spans are traced (behavior improvement,
  accepted).
- **Storage never crosses Boot's interface.** `StartFunc` opens everything
  the backend varies on and returns `(handler, shutdown, error)`; Boot
  never learns what a database is. The pg-specific pieces (`SetupDB`,
  goose migrations, the constraint registry, the tx runner) stay in
  `lib/database` as the Postgres adapter that pg backends wire inside
  their start hook — a future Mongo (or no-DB) Backend fills the same hook
  with its own adapter and Boot does not notice.
- **The constraint registry is data, not a global.** `SetupDB(cfg,
  messages ConstraintRegistry) (*pgxpool.Pool, error)` is the one writer;
  the per-backend `constraints.go` files shrink to a map literal. The
  init-order contract (2) is gone.
- **The tx runner is a dependency, not a global.** `SetDefaultRunner`,
  `RunTx`, and `RunTxWithOptions` are deleted; services that open
  transactions take `database.TxRunner` explicitly (the pattern univents
  already used). The init-order contract (3) is gone. The contract-1
  ordering (FUN before requests) is owned by Boot itself.
- **Boot returns an error; `errx.Exit` stays the process edge.** `cmd/main`
  calls `errx.Exit(app.Run(), ...)`. Library code no longer exits
  (`SetupDB`, client setup, river/riverui start return errors), so the
  boot path is testable through its interface.
- **The app singleton is gone.** `var app <Backend>` is deleted; `Run()`
  builds a local instance. Per-backend `app.go`/`run.go` collapse into one
  `Run()` with a start hook; the wire helpers (`initRepos`,
  `initOperations`, `initRiver`, …) stay as methods on the local struct.
  `httpserver.Start` (log.Fatal serving) is deleted — Boot serves.

## Consequences

- A boot-ordering bug is now a one-module question, not an archaeology
  dig; river migration placement is enforced by whoever owns the hook,
  with the same call (`libriver.Migrate`) in the same slot per backend.
- Backends that are not Postgres need no fork: Boot's interface never
  mentions storage.
- Unit tests construct what they need (`nopTxRunner` stubs) instead of
  mutating package globals; per-test isolation improves.
- `SetupFUN` still exits on interceptor-registration failure — a
  programmer error, not a boot condition; accepted.
- `telemetry.Log()` (global logger, `TEST_MODE` env branch) remains —
  real friction, but logger injection through every lib module is high
  churn for modest payoff this pass. Future work, deliberately deferred.
