## Why

Every backend's `Start()` wrote out the same 15 or so boot steps by hand: constraint registry, config, FUN, clients, `SetupDB`, tracer, tx runner, River, serve. The order lived in four places, and four "call this before that" rules were kept only by habit:

1. `SetupFUN` before any request is handled.
2. The constraint registry before `SetupDB` reads it.
3. `SetDefaultRunner` before the first `RunTx`.
4. The tracer before spans mean anything. Its place varied, so the spans for the database connection were lost.

The River migration had already drifted: in the app in Payssage, in wiring in IdentityX and Univents, missing in Informd. The app was a package global (`var app Informd`) changed by `Start()`, so the real wiring could only be tested by booting a whole process. And each boot assumed Postgres, so a backend on another store would have had to copy and change all of it.

## Decision

- **`httpserver.Boot(cfg, start)` runs the process.** In order: FUN, the tracer, the backend's own setup (the `start` hook), serving, then shutdown in reverse. The backend shuts down before the tracer, so spans from stopping workers are kept. The tracer now starts before the database opens, so connection spans are recorded.
- **Boot knows nothing about storage.** The `start` hook opens whatever the backend needs and returns `(handler, shutdown, error)`. The Postgres pieces (`SetupDB`, goose migrations, the constraint registry, the tx runner) stay in `lib/go/database` and are called from inside the hook. A backend on another store, or with none, fills the same hook its own way.
- **The constraint registry is a value.** `SetupDB(cfg, messages)` takes it as an argument, so each backend's `constraints.go` is just a map. Rule 2 is gone.
- **The tx runner is a dependency.** `SetDefaultRunner`, `RunTx` and `RunTxWithOptions` are deleted. Services that open transactions take a `database.TxRunner`, as Univents already did. Rule 3 is gone, and Boot itself enforces rule 1.
- **Boot returns errors.** Only `cmd/main` exits, with `errx.Exit(app.Run(), ...)`. Library code (`SetupDB`, client setup, River) returns errors instead of exiting, so boot can be tested.
- **No app global.** `var app <Backend>` is deleted. `Run()` builds a local instance, and each backend's `app.go` and `run.go` merge into one `Run()` with a start hook. `httpserver.Start` is deleted, because Boot serves.

## Consequences

- A boot-order bug is a question about one module, not four. The River migration is the same call (`libriver.Migrate`) in the same place in every backend.
- A backend that isn't on Postgres doesn't need a copy of the boot.
- Unit tests build what they need, like a `nopTxRunner`, instead of changing globals.
- `SetupFUN` still exits if an interceptor fails to register. That's a programming error, not a boot condition, and we accept it.
- `telemetry.Log()`, the global logger with its `TEST_MODE` branch, stays. Passing a logger through every lib module was too much churn for this change.
