  - api/univents/internal/services/badges

## Why

Informd, Payssage and Univents reached authorization through a package global, `var Service *service` in `internal/authz`. Boot set it in `wire.go`, and unit tests overwrote it directly. That caused problems:

- The setup order mattered but wasn't written anywhere, and there was no instance per request or per test.
- Access rules had no single home, so features drifted. `badges` shipped with no identity check and no role check, while every other feature started with `idx.RequireIdentity` and `CheckEvent`.

IdentityX already did it the other way: it passed `*authz.Service` into `services.NewOperations` and had no global.

## Decision

- In all three backends, export the type (`service` becomes `Service`) and delete `var Service`.
- Every feature's operations struct gets an `authz *authz.Service` field, passed in through `services.NewOperations`, as in IdentityX. `wire.go` builds the service once and passes it down. Tests build a fresh one per test the same way. The constructors already take ports (`ports.EventRepo`, `ports.FormsRepo`, `ports.OrganizationRepo`), so existing fakes still work.
- `badges` gets its missing guard on writes: `RequireIdentity` and `CheckEvent(..., EventMemberRoleAdmin)`, like `certifications`.

## Consequences

- The global is gone, and tests no longer change process state.
- A feature that takes authz in its constructor can't forget it the way `badges` did.
- Which role each operation needs is still written inline in each operation. Moving that into one table is a separate change.

## Rejected

- **Put authorization in the context.** Identity already travels there, but hiding authz in it would hide the dependency and bring back the same test problem.
- **One authz instance per feature.** No feature needs its own rules today. One per backend is enough.
