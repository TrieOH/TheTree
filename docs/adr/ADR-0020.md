# ADR-0020 — Public reads are kept at the edge until a write purges them

- **Status:** accepted
- **Date:** 2026-11-05
- **Scope:** `lib/go/{httpcache,authz,httpserver}`, `lib/ts/container-budget` (`edge`), `api/{identityx,informd,payssage,univents}` (specs, handlers, `cloudflare/`)

## Context

The containers scale to zero, so a request the edge cannot answer wakes
one: a cold start of about six seconds, and in the first days of the
cold-start dataset roughly half of Univents' cold starts failed. A week
of traffic showed most real reads are public and the same for every
caller (Univents' storefront lists, IdentityX's public profiles, every
Backend's spec and problem docs), and about a third of Univents' API
requests were CORS preflights, each reaching the container to say yes.

## Decision

- **Every response is `private, no-store` unless its operation opts in.**
  `lib/go/httpcache` writes the policy as the response starts; a
  Cache-Control the handler set itself stands.
- **An operation opts in with `x-cache: shared` in the spec.** The
  resolver (`lib/go/authz`) accepts it only on a public GET (a shared
  response must be the same for every caller) and fails the boot
  otherwise, as with `x-scope`. Only a 200 is stored. The policy is
  `Cache-Control: public, max-age=0, must-revalidate` (browsers always
  revalidate; nothing outside the edge keeps a copy it cannot drop) and
  `CDN-Cache-Control: max-age=604800` (a week, a backstop for a lost
  purge).
- **Tags name what a response holds; writes purge them.** Handlers call
  `httpcache.Tag` on reads and `httpcache.Purge` on writes, with names
  from the Backend's `internal/cachetags`: one tag per entity, one per
  collection. A write purges the entity it changed and the collections it
  sits in, nothing wider: the cached payloads embed no other entity's
  data. The tags go out as `Cache-Tag` and, on a 2xx only,
  `Cache-Purge-Tag`. They are plain headers; off Cloudflare a CDN that
  reads Cache-Tag can use them, and the purge list is ignored.
- **Responses that change only with a deploy** (`/docs/openapi.yml`,
  `/problems/{slug}`) are kept for a year: the edge cache is per Worker
  version, so a deploy starts it empty.
- **Each API Worker splits into a gateway and `Cached`.** The default
  entrypoint has no cache in front of it. It answers CORS preflights from
  the same `CORS_ALLOWED_*` vars the Backend reads, sends GET/HEAD reads
  (not streams or upgrades) to `Cached` through `ctx.exports`, sends
  writes to the container, strips `Cache-Purge-Tag` and purges. `Cached`
  has Workers Caching on (per-entrypoint `cache` in `wrangler.jsonc`) and
  stamps `private, no-store` on any response without a policy, so the
  cache's heuristic TTLs never apply. Purges only reach the cache of the
  entrypoint that calls them, so they run inside `Cached`, over RPC.
- **A refused purge is retried through the jobs queue** (`cache.purge`,
  every 30 seconds). Workers Caching always gets the Free plan's purge
  limits (five a minute, bursts of 25, per account).
- **The Backend still answers CORS.** Its preflight answer stays, with
  the same max age (two hours, Chrome's cap), so a Backend off Cloudflare
  behaves the same.

## Consequences

- Cached now: Univents' public events, by-slug event, public editions,
  and an edition's products, ticket types, programs and occurrences;
  IdentityX's project profile and profile by handle; every Backend's spec
  and problem docs.
- Caching another read is `x-cache: shared` on the operation, a `Tag` in
  its handler and a `Purge` in every handler that writes what it returns.
  A missing purge serves stale data for up to a week.
- A schema change purges every profile in its scope and every by-handle
  read, since profiles migrate when read.
- Writes made outside a request (jobs) purge nothing. None of today's jobs
  write a cached entity.
- Every read pays the tiered-cache lookup, including uncacheable
  authenticated GETs. With caching on, the gateway's call into `Cached`
  is billed as a request, so a read counts twice against the plan.
