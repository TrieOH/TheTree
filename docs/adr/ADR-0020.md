## Why

Containers scale to zero, so any request the edge can't answer wakes one up. A cold start takes about six seconds, and in the first days of collecting cold-start data, roughly half of Univents' cold starts failed. A week of traffic showed that most real reads are public and the same for every caller: Univents' storefront lists, IdentityX's public profiles, and every backend's spec and problem docs. And about a third of Univents' API requests were CORS preflights, each one reaching the container just to say yes.

## Decision

- **Every response is `private, no-store` unless its operation opts in.** `lib/go/httpcache` sets the policy as the response starts. A `Cache-Control` the handler set itself is kept.
- **An operation opts in with `x-cache: shared` in the spec.** The resolver (`lib/go/authz`) only allows it on a public GET, since a shared response must be the same for everyone, and stops the boot otherwise. Only a 200 is stored. The headers are `Cache-Control: public, max-age=0, must-revalidate`, so browsers always revalidate and nothing outside the edge keeps a copy we can't drop, and `CDN-Cache-Control: max-age=604800`, a week, as a backstop in case a purge is lost.
- **Tags say what a response holds, and writes purge them.** Handlers call `httpcache.Tag` on reads and `httpcache.Purge` on writes, with names from the backend's `internal/cachetags`: one tag per entity and one per collection. A write purges the entity it changed and the collections it's in, nothing wider, because cached payloads don't embed other entities. The tags go out as `Cache-Tag`, and on a 2xx also as `Cache-Purge-Tag`. They're plain headers: off Cloudflare, a CDN that reads `Cache-Tag` can use them, and the purge list is ignored.
- **Responses that only change on deploy,** `/docs/openapi.yml` and `/problems/{slug}`, are kept for a year. The edge cache is per Worker version, so each deploy starts it empty.
- **Each API Worker splits into a gateway and `Cached`.** The default entry point has no cache in front of it. It answers CORS preflights itself, from the same `CORS_ALLOWED_*` vars the backend reads. It sends GET and HEAD reads (not streams or upgrades) to `Cached` through `ctx.exports`, sends writes to the container, strips `Cache-Purge-Tag` and purges. `Cached` has Workers Caching on (`cache` per entry point in `wrangler.jsonc`) and stamps `private, no-store` on any response without a policy, so the cache never guesses a TTL. A purge only reaches the cache of the entry point that calls it, so purges run inside `Cached`, over RPC.
- **A refused purge is retried through the jobs queue** (`cache.purge`, every 30 seconds). Workers Caching always has the Free plan's purge limits: five a minute, bursts of 25, per account.
- **The backend still answers CORS.** Its preflight answer stays, with the same max age of two hours (Chrome's cap), so a backend off Cloudflare behaves the same.

## Consequences

- Cached today: Univents' public events, event by slug, public editions, and an edition's products, ticket types, programs and occurrences. IdentityX's project profile and profile by handle. Every backend's spec and problem docs.
- Caching another read means `x-cache: shared` on the operation, a `Tag` in its handler and a `Purge` in every handler that writes what it returns. A missing purge serves stale data for up to a week.
- A schema change purges every profile in its scope and every by-handle read, since profiles migrate when read.
- Writes made outside a request, by jobs, purge nothing. No job today writes a cached entity.
- Every read pays the tiered-cache lookup, including authenticated GETs that can't be cached. With caching on, the gateway's call into `Cached` is billed as a request, so each read counts twice against the plan.
