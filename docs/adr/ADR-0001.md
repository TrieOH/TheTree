## Why

Each backend started from a hand-copied `internal/app`: `server.go`, `fun.go`, `router.go` and the middleware setup in `wire.go`. The copies were nearly identical. `SetupIdentityX` was pasted four times too. Any change to how a server runs had to be made four times.

The copies had also drifted. Informd and Univents ran the full middleware stack (real IP, request ID, logger, metrics, recover, timeout, body size, rate limit, CORS). Payssage ran only the logger and CORS, and IdentityX ran logger, metrics and CORS with the rest commented out.

## Decision

Add `lib/go/httpserver` with three calls: `SetupFUN(appName)`, `NewRouter(Config)` and `Start(handler, Config)`. It owns:

- the server lifecycle: timeouts, listening, and pprof on `ProfilePort`
- the fun setup, including the logger for 500 responses
- the full middleware stack, on all four backends, with no opt-outs
- the router frame: `/metrics`, `/health`, and the otelhttp wrapper that skips both

Each backend passes its own routes in `Config.Routes` and its quiet log paths in `Config.SkipLogPrefixes`. `server.go` and `fun.go` are deleted.

A backend keeps only what is its own: config loading, feature wiring in `wire.go`, `auth.go`, constraint registries, jobs and its other clients.

`SetupIdentityX` moves into `sdk/identityx` as `Bootstrap(ctx, cfg)`. It now waits up to 5 seconds for the JWKS at startup instead of fetching it in the background.

## Consequences

- Payssage and IdentityX now run the full middleware stack. IdentityX drops `riandyrn/otelchi` for the shared otelhttp wrapper. The rate limit is 400 requests per second, burst 20, per `RemoteAddr`, everywhere.
- All four backends are on the same versions: chi v5.3.0, fun/middlewares v0.1.3, otelhttp v0.69.0, otel v1.44.0.
- `lib/go/httpserver` is tested through its own calls with httptest. We skipped per-backend smoke tests for now.
- Startup can wait up to 5 seconds on the JWKS fetch.

## Rejected

- **Keep the copies.** They were identical, so they protected no real difference, and every change stayed a 4× edit.
- **Separate `httpserver` and `router` packages.** Nothing needs one without the other.
- **A builder API.** Same result as a config struct with a callback, with more ceremony.
- **Per-backend flags to turn middlewares off.** No backend needs one. Getting Payssage and IdentityX onto the same stack was the point.
