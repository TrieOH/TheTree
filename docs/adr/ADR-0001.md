# ADR-0001 — Shared HTTP serving harness (`lib/httpserver`)

- **Status:** accepted
- **Date:** 2026-08-01
- **Scope:** `api/{identityx,informd,payssage,univents}/internal/app`, `lib/go/httpserver`

## Context

Every backend booted through a hand-copied `internal/app` skeleton: `server.go`
(differing only by service name), `fun.go` (two variants differing only by an
interceptor), `router.go` (same skeleton: chi → middleware stack → `/metrics` →
`/health` → otelhttp wrapper), and the middleware-stack construction in
`wire.go` (byte-identical blocks in informd and univents, a reduced stack in
payssage and identityx). `SetupIdentityX` (identityx SDK client + JWKS
prefetch) was copy-pasted four times with only config-type differences. A
harness change had to be made four times.

The 9-middleware standard stack (realIP, requestID, logger, metrics, recover,
timeout, bodySize, ratelimit, cors) existed in full only in informd and
univents; payssage ran logger+cors, identityx logger+metrics+cors with the
others commented out.

## Decision

Introduce **`lib/go/httpserver`**: one deep module with a small interface —
`SetupFUN(appName)`, `NewRouter(Config)`, `Start(handler, Config)` — that owns:

- server lifecycle (timeouts, listen, pprof on `ProfilePort`),
- fun configuration incl. the 500-response logger interceptor,
- the standard 9-middleware stack (applied to **all four** backends; no
  opt-out flags until a backend actually needs one),
- the router skeleton (`/metrics`, `/health`, otelhttp wrapper skipping both),
- per-backend differences arriving via `Config.Routes func(*chi.Mux)` and
  `Config.SkipLogPrefixes`.

Each backend keeps only: config loading, `wire.go` feature wiring, `auth.go`,
constraint registries, job bootstrapping, and its non-identityx clients
(resty, objectstorage, email). Its `CreateRouter` becomes a thin `Routes`
closure; `server.go`/`fun.go` are deleted (replace, don't layer).

`SetupIdentityX` folds into `sdk/identityx` as `Bootstrap(ctx, cfg)` (blocking
JWKS verification with a 5s timeout; previously async with a goroutine).

## Consequences

- **Behavior change (accepted):** Payssage gains the standard stack
  (recover, timeout, bodySize, ratelimit, realIP, requestID); identityx gains
  the same and drops `riandyrn/otelchi` in favor of the shared otelhttp
  wrapper. Rate limit is 400 RPS / burst 20 keyed on RemoteAddr everywhere.
- **Version convergence:** all four backends moved to chi v5.3.0,
  fun/middlewares v0.1.3, otelhttp v0.69.0, otel v1.44.0 (the harness pins
  these for the whole workspace).
- **Tests:** `lib/httpserver` is tested at its interface (health, metrics,
  routes callback, middleware behaviors) via httptest. Per-backend smoke tests
  were considered and rejected for now.
- `SetupIdentityX` startup now blocks up to 5s on JWKS fetch instead of
  fetching in the background.

## Rejected alternatives

- **Keep per-service copies** — a harness change remains a 4× edit; the
  copies were byte-identical, so no per-service variation was being preserved.
- **Split `lib/httpserver` and `lib/router`** — two shallower modules, no
  caller needs one without the other.
- **Builder-style interface** — same depth, more ceremony than a Config
  struct + callback.
- **Per-backend middleware opt-out flags** — YAGNI; payssage and identityx
  converging on the standard stack was the point.
