## Why

ADR-0016 named the errors and put HTTP mapping in one switch. ADR-0019 declared each problem in YAML. So an error a client could see lived in three places: its sentinel in `errs`, its problem in `problems.yml`, and a case in the mapper joining them. Of about 220 cases, 198 were the same two lines, `errors.Is(err, errs.ErrX)` returning `problems.X(errs.ErrX.Error())`. A problem declared but never mapped became a silent 500.

The messages were weak too. A sentinel's text is the problem's `detail`, and most just repeated the title (`invalid kid`, `invalid request`) or named the failure without saying what to do.

## Decision

- **A problem with no extra fields names its sentinel and the sentinel's text** in its `x-problem`:

  ```yaml
  AddSelfToOrg:
    x-problem:
      slug: add-self-to-org
      status: 400
      title: Add Self To Org
      description: "Users can't add themselves to organizations."
      error: ErrAddSelfToOrg
      message: "you can't add yourself to an organization; ask one of its admins or its owner to add you"
  ```

  `tools/problemgen` generates the sentinel into the backend's `errs/errs.gen.go` (gitignored, like the rest of its output), and `problems.Mapper` answers it with its problem, after the backend's own switch and before the shared cases. `error` and `message` don't go into the bundle.
- **The message is the detail a client reads,** so it says what went wrong and what to do about it, in Go error style: lowercase and no final punctuation, though a name like `IdentityX` can start it. `problemgen` rejects a message that repeats the title or breaks that style.
- **Only errors a problem can't name are written by hand in `errs`:** typed errors that carry the problem's fields (and the cases that pick a problem based on them), named errors answered with a shared problem (`Unauthenticated`, `InvalidToken`), the not-found errors and the check constraints. The backend's `Problem` switch maps those.
- **Shared problems in `api/problems.yml` name no error.** They answer `lib` errors, mapped in the generated shared cases.

## Consequences

- A new error a client can see is one YAML entry. The mapper can't miss it, because the problem and its error are the same declaration.
- `Problem(err)` alone no longer answers a declared sentinel, so tests that check a status go through `problems.Mapper(Problem)`.
- The sentinels' doc comments moved to YAML comments next to `error`.
- The shared `lib` errors were rewritten the same way, so every detail a client reads says what to do next.
