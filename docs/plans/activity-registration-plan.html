Univents · Feature Plan

Activity Registration

Let attendees sign up for event activities themselves — and give organizers a clean way to mark who actually showed up.

Attendees browse the event schedule, pick an activity, and sign up on the spot — no staff involved. Organizers see the participant list for every activity and mark attendance. Once someone is marked as attended, their spot is locked: it can no longer be cancelled, keeping attendance records trustworthy.

The feature at a glanceWhat it does

🙋

Attendees

Sign up and drop out of activities themselves, and see a personal "my activities" schedule.

🎫

Access rules

Only attendees with a valid ticket can sign up, and only for activities their ticket level allows.

✅

Organizers

Open any activity's participant list and mark who attended. Marked attendees can't back out.

We asked to build four things, and this plan covers exactly that:

  • Registration — an attendee signs themselves up for an activity session.
  • De-registration — they can cancel their spot any time before the activity, freeing it for someone else.
  • Marking attendance — staff mark who showed up.
  • Locking de-registration — once attendance is marked, the spot can no longer be cancelled.

Step by stepHow it works

  1. An attendee opens the event's schedule page — it's public, anyone can browse the activities and their sessions.
  2. They sign in and hit "Sign up" on a session. If their ticket allows it and there's room, it's theirs.
  3. Their sign-ups show up under "My activities" — one place with everything they've joined.
  4. Changed plans? They hit "Cancel". The spot opens up for the next person. (Free, no penalty.)
  5. On the day, staff open the activity's participant list and mark each person as attended.
  6. Once marked, that person's spot is locked — it can't be cancelled anymore, by anyone.

Simple, clear rulesThe rules

  • A ticket is required. You need a confirmed (paid) ticket to sign up for activities. Unpaid reservations can't hold activity spots.
  • Ticket level matters. Some activities require a higher ticket level, or are staff-only. The system checks and politely declines if you don't qualify.
  • Capacity is enforced. Each session has a maximum number of spots. When it's full, sign-up is declined with a clear message.
  • One spot per person, per session. No double sign-ups.
  • Cancelling is always allowed — until attendance is marked. That's the lock.
  • History is kept. If someone signs up, cancels, signs up again, that trail stays visible to organizers. Your personal "my activities" view only ever shows your current sign-ups.

For the engineersImplementation details

Data model — reuse, don't reinvent

The activity-sign-up table (program_participations) already exists and already holds the statuses we need (registered → attended / no_show / cancelled). Today it's only written by the paid checkout flow; this feature opens it up to self-service. Key mechanics:

  • Register inserts a row (status = registered).
  • De-register flips the row to cancelled — never deletes. The table is an append-only ledger: sign-up churn leaves a visible trail for staff, mirroring how ticket registrations already behave. "My activities" reads only the active (non-cancelled) rows.
  • Mark attendance flips registered → attended with a guarded update (WHERE status = 'registered') — the row itself is the lock; a cancelled spot can never be marked attended.
  • Capacity + anti-double-signup: new partial unique index (occurrence_id, registration_id) WHERE status IN ('registered','attended','no_show') — the database rejects a racing double sign-up atomically. Register runs in a tx with a row lock on the occurrence (existing pattern).
  • Availability moves to one pool: occurrence stock is computed from participations instead of purchase items — paid spots already materialize a participation, so numbers stay identical for existing data and self-sign-ups count automatically. Register/deregister publish the store's stock notification so live stock streams stay fresh.

API surface

Read seams stay orthogonal: the public schedule stays stateless and anonymous; personal state comes only from "My activities"; stock numbers live on the store's existing realtime surface. No BFF-style enrichment on shared reads.

Phase 4Tests
  • Register: happy path · no ticket / low level / staff-only → 403 · full → 409 · double sign-up → 409 (incl. racing insert) · unknown → 404.
  • De-register: happy path · attended/no_show → 409 lock · not signed up → 404.
  • Mark attended: staff vs attendee → 403 · cancelled → 409 · idempotent re-mark.
  • Availability: sign-up moves the number · stock notify on register/deregister · refund/expiry frees the slot.

Later / follow-ups
