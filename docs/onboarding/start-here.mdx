# Start here

- **Order:** 1
- **Summary:** What TrieOH is, how to contribute, and the order to read these docs in.

TrieOH builds four products. They live in one repo, TheTree, because they share code and depend on each other.

| Product | What it does |
| --- | --- |
| IdentityX | Login, accounts, organizations, projects and API keys |
| Payssage | Payments through MercadoPago |
| Informd | Forms and their responses |
| Univents | Events: tickets, check-in, badges and certificates |

Each product is a Go API plus a web app. Every app signs in through IdentityX, and Univents takes payments through Payssage.

You're reading the dev portal. It shows our docs, issues, deploys and metrics, and anyone can read it. We work in the open.

## How contributing works

1. Pick an issue from the Issues page, or open one on GitHub for a bug or an idea.
2. Fork TheTree, make the change on a branch, and open a pull request.
3. Someone on the team reviews it. Once it's merged, the team ships it.

You don't need any account other than GitHub. Everything runs on your machine.

## Two rules to know on day one

1. **Git hooks check your work.** `pnpm install` sets them up, and they run when you commit and push. When one fails, fix what it reports and try again. Don't skip them with `--no-verify`.
2. **Tags deploy to production.** A tag like `payssage/v0.7.10` ships that API. Only the team pushes tags, so you'll never need to. Merging to `main` deploys nothing.
