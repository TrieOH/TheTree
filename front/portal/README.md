# portal

The TrieOH dev portal: docs, services and the state of TheTree for the people who build it. One Worker serves the Solid SPA, its read API over D1 and, as later phases land, the Linear/GitHub/deploy webhooks and the analytics crons.

**Hard rule:** nothing the portal reads may wake a container or a database. No calls to the four APIs, no Postgres, no `/health` polling. Every number comes from outside the services (Linear, GitHub, Cloudflare analytics, Grafana Cloud, Neon's control plane) and is stored in D1 first.

## Layout

Same stack and structure as `front/univents-solid` (Solid 2, TanStack Solid Router, Tailwind 4, `@cloudflare/vite-plugin`).

- `src/server.ts`: `/api/*` (reads D1), `/webhooks/*`, everything else → ASSETS.
- `src/routes/`: Home, Services, Issues, Delivery, Metrics, Docs.
- `src/features/docs/`: docs come from the repo's `docs/` at build time. `docs/adr/*.md` are compiled by MDX (`mdx/remark-adr.ts` lifts the number, title, status and date into `meta`) and rendered through `src/shared/mdx/jsx-runtime.ts`.
- `src/features/issues/`: Linear. `POST /webhooks/linear` checks the HMAC signature and the signed timestamp, drops redeliveries and upserts into D1. An hourly cron (`syncLinear`) pulls what changed since its last run with the read-only key; its first run is the backfill. Issues map to a service through their Linear project. `GET /api/issues` serves the Issues page, the service pages and Home.
- `src/features/delivery/`: GitHub and deploys. `POST /webhooks/github` (repo webhook: pull_request, pull_request_review, workflow_run, push for tags) checks `X-Hub-Signature-256` and dedupes on `X-GitHub-Delivery`. `POST /webhooks/deploy` and `POST /webhooks/ci` take what the `report` job of `deploy.yml` sends after every release run (`.github/actions/release/report`): the outcome and the stage it stopped at, then every job's and step's start and end and the metrics the actions recorded (`ci_*` tables). `GET /api/delivery` serves the Delivery page, including step times per pipeline. History from before the hooks: `scripts/backfill-github.mjs`.
- `src/features/api-reference/`: `/services/<svc>/api`. `mdx/api-plugin.ts` turns `api/<svc>/api-spec.gen.yml` (generated by `just gen`, and by CI before every front build) into a small model at build time: validated with `@scalar/openapi-parser`, schemas kept by name, examples from `openapi-sampler`, descriptions through remark, every real host replaced by `{API_URL}`. The page renders it with portal components; nothing on it can call an API.
- `src/features/problems/`: `/problems/<svc>` and `/problems/<svc>/<slug>`, and the `<Problems>` doc component, from `api/problems.yml` and `api/<svc>/problems.yml`.
- `migrations/`: D1 schema.

## Query the data

Everything under `/api` is public and read-only, with open CORS, so a script or an agent can ask the portal directly instead of calling GitHub, Linear or Grafana. `GET https://portal.trieoh.com/api/ci` lists the CI endpoints and their filters.

| Endpoint | One row per |
|---|---|
| `/api/ci/runs` | release run, with `duration_ms` |
| `/api/ci/runs/{run_id}` | one run in full: jobs (with `queue_ms`), their steps, each step's substeps, and the metrics |
| `/api/ci/steps` | top-level step per run, with `duration_ms` |
| `/api/ci/substeps` | action inside a composite step, with the step it ran in |
| `/api/ci/metrics` | number an action recorded with `.github/scripts/metric` |

Every list takes `type`, `component`, `tag`, `status`, `stage`, `lane`, `since` and `until`, newest first, plus `limit` (default 200, at most 5000) and `format=csv`. Steps and substeps also take `job` and `name` (substeps: `step` for the step's name), metrics take `job`, `source`, `name` and `label.<key>=<value>`. For example:

```sh
# how long Setup Node + pnpm took in every front run this week, as CSV
curl 'https://portal.trieoh.com/api/ci/steps?type=front&name=Setup%20Node%20%2B%20pnpm&since=2026-11-01&format=csv'
# what inside it took the time
curl 'https://portal.trieoh.com/api/ci/substeps?type=front&step=Setup%20Node%20%2B%20pnpm'
```

## Develop

```sh
pnpm -F portal db:migrate:local   # once, and after adding a migration
pnpm -F portal dev                # http://localhost:3010
pnpm -F portal tsc && pnpm -F portal check && pnpm -F portal test
```

## Secrets

`wrangler secret put` on the `portal` Worker: `LINEAR_API_KEY` (personal key, read-only, team TRI) and `LINEAR_WEBHOOK_SECRET` (the signing secret of the Linear webhook pointing at `https://portal.trieoh.com/webhooks/linear`, events Issues, Cycles and Projects). `GITHUB_WEBHOOK_SECRET` is the secret of the repo webhook pointing at `https://portal.trieoh.com/webhooks/github`. `DEPLOY_HOOK_SECRET` is shared with the GitHub Actions secret of the same name.

## Deploy

Tag `portal-ui/vX.Y.Z` (see `.github/workflows/_front.yml`): checks and one build, then D1 migrations and `wrangler deploy` of that build with `PORTAL_CLOUDFLARE_API_TOKEN`.
